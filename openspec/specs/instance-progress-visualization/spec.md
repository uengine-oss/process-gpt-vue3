# instance-progress-visualization Specification

## Purpose
프로세스 모니터링 화면이 인스턴스의 진행 상태를 BPMN 다이어그램 위에 어떻게
표현하는지를 규정한다. 특히 액티비티 도형뿐 아니라 **토큰이 이미 흘러간 연결선과
그 사이의 게이트웨이·이벤트**를 어떻게 강조하는지를 다룬다.

## Requirements

### Requirement: 흘러간 연결선은 두꺼운 실선으로 강조된다

프로세스 모니터링 화면은 토큰이 이미 지나간 시퀀스 플로우를 강조해야 한다(MUST).
강조는 완료 액티비티 테두리와 같은 색의 두꺼운 실선으로 표시하며, 강조된 연결선의
선 굵기는 강조되지 않은 연결선보다 굵어야 하고 점선이 아니어야 한다(MUST).

토큰이 아직 떠나지 않은 노드(실행중·대기중 액티비티)의 나가는 연결선은
강조하지 않아야 한다(MUST NOT).

#### Scenario: 완료 액티비티에서 실행중 액티비티로 이어지는 구간

- **GIVEN** A → B → C 순서의 프로세스 인스턴스를 모니터링 중이고
- **AND** A는 완료, B는 실행중 상태이고
- **WHEN** 진행 상태 다이어그램이 렌더링되면
- **THEN** A와 B를 잇는 연결선은 두꺼운 실선으로 강조되어야 한다
- **AND** B와 C를 잇는 연결선은 강조되지 않아야 한다

#### Scenario: 아직 아무 액티비티도 완료되지 않은 인스턴스

- **GIVEN** 첫 액티비티만 실행중이고 그 앞에 시작 이벤트가 있는 인스턴스를 모니터링 중이고
- **WHEN** 진행 상태 다이어그램이 렌더링되면
- **THEN** 시작 이벤트에서 첫 액티비티로 들어오는 연결선은 강조되어야 한다
- **AND** 첫 액티비티에서 나가는 연결선은 강조되지 않아야 한다

#### Scenario: 종료까지 완료된 인스턴스

- **GIVEN** 마지막 액티비티까지 완료된 인스턴스를 모니터링 중이고
- **WHEN** 진행 상태 다이어그램이 렌더링되면
- **THEN** 마지막 액티비티에서 종료 이벤트로 가는 연결선까지 강조되어야 한다

### Requirement: 게이트웨이를 사이에 둔 구간도 이어서 강조된다

모니터링 화면은 상태가 없는 통과 노드를 관통하는 구간의 연결선도 강조해야 한다(MUST).
통과 노드란 게이트웨이와 시작·중간·종료 이벤트를 말한다. 진행 상태는 액티비티 단위로만
제공되고 게이트웨이·이벤트에는 상태가 없으므로, 프로세스 정의의 흐름을 따라가
지나간 구간을 판별한다.

강조된 경로 위에 놓인 통과 노드 자체도 연결선과 같은 강조로 표시하여
경로가 끊겨 보이지 않아야 한다(SHALL).

#### Scenario: 완료 액티비티와 실행중 액티비티 사이에 게이트웨이가 있는 경우

- **GIVEN** A → 게이트웨이 → B 구조의 인스턴스를 모니터링 중이고
- **AND** A는 완료, B는 실행중 상태이고
- **WHEN** 진행 상태 다이어그램이 렌더링되면
- **THEN** A에서 게이트웨이로 가는 연결선이 강조되어야 한다
- **AND** 게이트웨이에서 B로 가는 연결선이 강조되어야 한다
- **AND** 그 게이트웨이 도형도 같은 강조로 표시되어야 한다

#### Scenario: 게이트웨이를 여러 개 관통한 경우

- **GIVEN** 분기 게이트웨이와 병합 게이트웨이를 모두 지나온 인스턴스를 모니터링 중이고
- **WHEN** 진행 상태 다이어그램이 렌더링되면
- **THEN** 분기 게이트웨이부터 병합 게이트웨이를 거쳐 현재 지점까지의 연결선이 모두 강조되어야 한다

### Requirement: 실행되지 않은 분기는 강조되지 않는다

분기 게이트웨이에서는 실제로 선택된 갈래만 강조해야 한다(MUST).
어느 갈래를 선택했는지 진행 상태로부터 단정할 수 없는 경우에는
어느 갈래도 강조하지 않아야 한다(MUST NOT) — 잘못된 경로를 강조하는 것보다
표시하지 않는 편을 택한다.

모든 갈래가 동시에 실행되는 병렬 분기에서는 모든 갈래를 강조해야 한다(MUST).

#### Scenario: 배타 분기에서 한쪽 갈래만 실행된 경우

- **GIVEN** 배타 게이트웨이가 갈래 B와 갈래 C로 나뉘는 인스턴스를 모니터링 중이고
- **AND** 갈래 B의 액티비티에는 실행 흔적이 있고 갈래 C의 액티비티에는 없고
- **WHEN** 진행 상태 다이어그램이 렌더링되면
- **THEN** 게이트웨이에서 갈래 B로 가는 연결선만 강조되어야 한다
- **AND** 게이트웨이에서 갈래 C로 가는 연결선은 강조되지 않아야 한다
- **AND** 갈래 C가 병합 지점으로 들어가는 연결선도 강조되지 않아야 한다

#### Scenario: 워크아이템이 미리 생성된 액티비티

- **GIVEN** 아직 시작되지 않은 액티비티의 작업 항목이 미리 생성되어 있고
- **WHEN** 진행 상태 다이어그램이 렌더링되면
- **THEN** 해당 액티비티로 향하는 분기는 실행 흔적으로 간주되지 않아야 한다

### Requirement: 진행 상태가 갱신되면 이전 강조가 남지 않는다

모니터링 화면이 새로운 진행 상태를 받으면 흘러간 경로 강조를 다시 계산해야 하며(MUST),
직전 상태에서 강조되었지만 새 상태에서는 강조 대상이 아닌 연결선과 통과 노드의
강조는 제거되어야 한다(MUST).

#### Scenario: 진행이 되돌려지거나 다른 인스턴스로 전환된 경우

- **GIVEN** 여러 게이트웨이를 관통한 경로가 강조되어 있는 상태이고
- **WHEN** 첫 액티비티만 실행중인 진행 상태로 화면이 갱신되면
- **THEN** 시작 이벤트에서 첫 액티비티로 들어오는 연결선만 강조되어야 한다
- **AND** 이전에 강조되었던 연결선과 게이트웨이의 강조는 모두 사라져야 한다

### Requirement: 분기 판단 이력이 있으면 사실을 쓰고 없으면 추론한다

모니터링 화면은 판단 이력이 있는 지점에서는 이력의 선택 결과를 그대로 사용해야 한다(MUST).
이력이 없는 판단 지점에서는 프로세스 정의 그래프를 이용한 추론을 유지해야 한다(MUST).
이력의 유무는 판단 지점 단위로 판별해야 하며,
인스턴스 단위로 둘 중 하나만 선택해서는 안 된다(MUST NOT) — 이력은 워크아이템이 완료될 때부터
쌓이므로 한 인스턴스 안에 이력이 있는 구간과 없는 구간이 함께 존재한다.

이력에 따라 선택되지 않은 갈래는 그 갈래의 하위 구간까지 함께 강조에서 제외되어야 한다(MUST).

판단 이력 조회가 실패하거나 지연되더라도 진행 표시는 추론만으로 계속 동작해야 하며(MUST),
화면이 비거나 오류를 표시해서는 안 된다(MUST NOT).

#### Scenario: 추론이 판정할 수 없는 분기를 이력이 확정한다

- **GIVEN** 배타 분기의 모든 갈래가 서로 다른 종료 이벤트로만 이어지는 인스턴스를 모니터링 중이고
- **AND** 그 분기에 대한 판단 이력이 존재한다
- **WHEN** 진행 상태 다이어그램이 렌더링되면
- **THEN** 이력이 선택했다고 알려준 갈래가 종료 이벤트까지 강조되어야 한다
- **AND** 선택되지 않은 갈래는 강조되지 않아야 한다

#### Scenario: 추론이 과잉 표시하던 분기를 이력이 교정한다

- **GIVEN** 두 갈래가 통과 노드만 거쳐 다시 합류하여 추론만으로는 양쪽이 모두 강조되는 인스턴스가 있고
- **AND** 그 분기에 대한 판단 이력이 존재한다
- **WHEN** 진행 상태 다이어그램이 렌더링되면
- **THEN** 이력이 선택한 갈래만 강조되어야 한다
- **AND** 선택되지 않은 갈래와 그 하위 구간이 모두 강조에서 제외되어야 한다

#### Scenario: 이력이 다루지 않는 구간은 추론이 메운다

- **GIVEN** 판단 이력이 존재하는 인스턴스를 모니터링 중이고
- **AND** 시작 이벤트에서 첫 활동으로 들어오는 구간은 이력에 남지 않는다
- **WHEN** 진행 상태 다이어그램이 렌더링되면
- **THEN** 해당 구간은 추론에 따라 강조되어야 한다

#### Scenario: 판단 이력이 없는 인스턴스

- **GIVEN** 판단 이력이 도입되기 전에 실행된 인스턴스를 모니터링 중이다
- **WHEN** 진행 상태 다이어그램이 렌더링되면
- **THEN** 강조 결과가 이력 기능 도입 이전과 동일해야 한다

#### Scenario: 판단 이력 조회 실패

- **WHEN** 판단 이력 조회가 실패한다
- **THEN** 진행 표시는 추론 결과로 정상 렌더링되어야 한다
