# Feature Specification: SOLiD AX 설명회 — Process GPT 전체 시연 데이터·시나리오

**Feature Branch**: `015-solid-ax-demo`

**Created**: 2026-10-08

**Status**: Implemented (2026-10-12) — 시드·사례 카드·진행안·대본·리허설 재생. 2026-10-14 장면 ⑥ 라이브 실행 확인(KPI 분석 에이전트 → 온톨로지 MCP), 설명회 슬라이드 15장(세션 1~3·6, 원본 `docs/demo/solid-ax/deck/`). 남은 것: 대괄호 자리(일자·담당자·투표 결과) 채우기, 유엔진 사례 고객사명 공개 범위 확인.

**Input**: 고객(쏠리드) 요청 B(단기 목표) — 오프라인 미팅/설명회로 (1) AX 선도 기업이 CASE1(특정 영역 내부 에이전트)·
CASE2(내부 에이전트 + 중장기 전사 AI + AI 에 맞는 BPM 재설계)·CASE3(완성형 AI 솔루션 도입)으로 어떻게 준비·실행·
성과를 얻는지 Use Case 몇 건과 함께 듣고, (2) 유엔진 솔루션으로 SOLiD 에 어떤 AX 체계를 구축할 수 있는지 알고 싶다.
이를 위해 Ontology Explorer 를 포함한 **Process GPT 전체**의 시연과 시나리오를 준비한다.

**근거 문서**: `쏠리드(SOLiD) AX 제안 전략 플랜.pdf` (2026-10-06, 유엔진) — 설명회 구성(6세션·2시간 30분),
CASE 층위 권고, Use Case 표(출처 포함), 인당 공헌이익 KPI 트리(목표 1·동인 3·핵심 프로세스 5), 4단계 로드맵.

## 원칙

- **사실과 가정을 섞지 않는다.** 쏠리드 수치는 공개자료(PDF 출처)만 쓰고, 데모 수치는 "가상 예시"로 화면·대본에 명시.
- **타사(P5.4.3 등 기존 고객) 프로세스·데이터를 쓰지 않는다.** SOLiD 데모 테넌트는 새로 만든다.
- **고객사명 사례(SKT·한전)는 공개 범위 확인 전 "확인 필요" 표시**를 유지한다(PDF 주의 사항).
- 데모는 화면만으로 설명되어야 한다 — 시나리오의 각 장면에 "이 화면이 답하는 질문"을 적는다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - SOLiD 데모 테넌트·데이터 (Priority: P1)

발표자가 시드 스크립트 한 번으로 SOLiD 데모 테넌트를 만든다: 북극성(인당 공헌이익) → 동인 3 → KPI → 핵심 프로세스
5(신제품 개발·수주/RFP 대응·품질 이슈→개선·공급망 납기 리스크·기술지원/인증 문서)의 BPMN 정의, 사람·에이전트·스킬,
그리고 수십 건의 실행 이력(병목·지연 포함). 정리(`--cleanup`)도 한 번에 된다.

**Independent Test**: 시드 후 전략 보드·온톨로지 익스플로러·분석 대시보드·프로세스 정의 화면에서 SOLiD 데이터가
풍부하게(프로세스 5·인스턴스 50+·사람/에이전트 10+) 보이고, 미달 KPI 1개 이상에서 원인 경로가 나온다.

### User Story 2 - 라이브 데모 시나리오(세션 4, 30분) (Priority: P1)

발표자가 대본대로 시연한다: ① SOLiD KPI 트리를 얹은 전략맵 → ② 미달 KPI(예: 제안 리드타임) 역추적(익스플로러 코스·
원인 분석) → ③ 딥링크로 병목 프로세스 정의를 그 자리에서 수정 → ④ "수주/RFP 대응" 또는 "공급망 납기 리스크"
프로세스를 사람–에이전트 혼합으로 실행(에이전트 초안, 사람 승인) → ⑤ 실행 결과가 KPI 로 집계되는 것 확인 →
⑥ (014) 에이전트가 MCP 로 온톨로지에 묻고 경로가 지도에 그려지는 장면.

**Independent Test**: 리허설 1회를 Playwright 로 자동 재생해 각 장면 스크린샷이 나오고, 대본의 장면별 소요 시간 합이 30분 이내.

### User Story 3 - 선도 기업 사례 세션 자료(세션 2) (Priority: P2)

CASE1·2·3 별로 "준비 → 실행 → 성과" 를 정리한 사례 카드(출처 링크 포함). PDF 의 사례(유엔진 2건 + Nokia·서연이화·
삼성SDS 패브릭스·국내 M.AX 통계)를 바탕으로 하되 공개 출처를 재확인하고, 회사 주장 수치는 "회사 발표 기준" 으로 표기.

### User Story 4 - SOLiD AX 체계 제안 화면(세션 3·6) (Priority: P2)

"유엔진 솔루션으로 SOLiD 에 구축할 AX 체계" 를 4계층(데이터 연동 → 온톨로지 → 멀티 에이전트 → 에이전틱 프로세스
관리) 위에 SOLiD 5개 프로세스를 얹은 그림·로드맵(설명회 → 진단 4~6주 → 파일럿 → 확산)으로 보여 준다.

### Edge Cases

- 설명회장 네트워크 불가: 로컬 스택만으로 시연 가능해야 한다(오프라인 LLM 불가 시 녹화본 백업).
- LLM 응답 지연: 에이전트 초안 장면은 사전 실행된 인스턴스로 대체 가능한 분기 대본을 둔다.
- 프로젝터 가독성: 1920×1080, 확대 125% 기준으로 리허설 스크린샷을 검수.

## Requirements *(mandatory)*

- **FR-001**: `scripts/demo/seed-solid-ax-demo.py` — SOLiD 데모 테넌트 시드/정리(멱등).
- **FR-002**: 5개 핵심 프로세스 BPMN(사람·에이전트 태스크, 승인 게이트, DMN 규칙 1개 이상).
- **FR-003**: KPI 트리(인당 공헌이익 → 동인 → KPI) 와 프로세스 연결, 실행 이력에서 KPI 집계.
- **FR-004**: 시연 대본 `docs/demo/solid-ax/scenario.md` — 장면별 화면·클릭·멘트·답하는 질문·소요 시간·실패 시 분기.
- **FR-005**: 리허설 자동화 스크립트(Playwright) + 장면 스크린샷.
- **FR-006**: 사례 카드 자료 `docs/demo/solid-ax/cases.md`(출처 링크 필수) 및 설명회 슬라이드(세션 1~3·6).
- **FR-007**: 매뉴얼/발표자 가이드(write-feature-manual 규약, 데이터 풍부).

## Success Criteria *(mandatory)*

- **SC-001**: 시드 1회로 모든 시연 화면이 데이터로 채워짐(빈 화면 0).
- **SC-002**: 리허설 자동 재생 성공, 세션 4 대본 30분 이내.
- **SC-003**: 사례 카드의 모든 수치에 출처가 있음(출처 없는 수치 0).
- **SC-004**: 데모 수치가 쏠리드 실적처럼 보이는 표현 0(모든 데모 화면에 "가상 예시" 표기).

## Assumptions

- 설명회 형식은 PDF 구성안(2시간 30분, 사장·개발·품질·SCM·영업 임원) 을 따른다.
- 시연 대상: Process GPT(정의·실행·채팅/에이전트), 전략 보드·온톨로지 익스플로러·분석 대시보드, PAL(프로세스 자산), 014 의 MCP/질의 경로.
- 쏠리드 내부 시스템(ERP·PLM·QMS) 은 미확인 — 데모는 가상 시스템 이름으로 표현하고 사전 질문지로 보정한다.
