# Task Catalog — 카탈로그 페이지 직접 등록 테스트 가이드

대상 기능: 관리자 콘솔 카탈로그 페이지(`/admin-console/task-catalog`)에서의 Task 등록·수정·삭제
관련 매뉴얼: `task-catalog-direct-registration-manual.md`

## 준비

- [ ] PAL 모드 테넌트에 관리자 계정으로 로그인
- [ ] (권장) 속성 스키마 스튜디오에서 테스트용 사용자 정의 속성 2개 준비
  - 예: `모든 Task` 대상 텍스트 필드 1개, `사용자 작업(bpmn:UserTask)` 대상 **필수** 셀렉트 필드 1개

## TC-1. 페이지 진입 및 구조

| 단계 | 기대 결과 |
|---|---|
| 사이드바 관리자 메뉴 → 카탈로그 클릭 | `/admin-console/task-catalog` 진입 |
| 페이지 헤더 확인 | 다른 관리자 콘솔 화면과 동일한 구조: 제목 "Task 카탈로그" + 부제 + 우측 "Task 추가" 버튼 |
| 헤더 아래 확인 | 검색/유형 필터 툴바 + 카드 그리드 렌더 |
| 항목을 10개 이상 등록(또는 창 높이 축소) | 카드 그리드 영역만 스크롤되고 헤더·툴바는 고정 |
| 등록 항목이 없는 테넌트 | "등록된 Task가 없습니다" 안내 표시 |

## TC-2. 기본 등록 (이름 + 유형만)

| 단계 | 기대 결과 |
|---|---|
| Task 추가 클릭 | 다이얼로그 열림, 제목 "Task 추가", 상단에 Task 유형 선택 + 아래에 패널형 섹션(일반 등) 렌더 |
| 일반 섹션의 이름을 비운 채 저장 클릭 | 이름 필수 검증으로 저장되지 않음 |
| 유형 `사용자 작업` 선택, 일반 섹션에서 이름 `결재 요청` 입력 후 저장 | 다이얼로그 닫힘, 목록에 `결재 요청` 카드 표시 (유형 칩: 사용자 작업) |

## TC-3. 패널 동등 렌더링 확인 (핵심)

| 단계 | 기대 결과 |
|---|---|
| Task 추가 → 유형 `사용자 작업` 선택 | 접이식 섹션들이 패널과 같은 구성·순서로 표시: 일반(이름·설명·무그룹 커스텀 필드) → 사용자 정의 그룹 → 폼 연결(자리표시) → RACI → 세부 업무 수행 절차 → 관련자료 링크 → API 연동 등(자리표시) |
| 순서도에서 아무 UserTask의 속성패널(Task 탭)과 비교 | 섹션 제목·아이콘·순서·사용자 정의 필드 구성이 동일 (순서도 전용 섹션은 "순서도에서 설정" 자리표시) |
| 섹션 제목 클릭 | 해당 섹션 접힘/펼침 토글 |
| 유형을 `서비스 작업` 등으로 변경 | 표시 섹션·필드가 유형 기준으로 갱신 (예: `사용자 작업` 전용 필수 필드 사라짐) |
| 필수 셀렉트 필드를 비운 채 확인 | 하단에 "필수: <필드명>" 경고 + 저장 버튼 비활성 |
| 필수 필드 입력 | 경고 사라지고 저장 가능 |
| RACI에 R 조직 1개, 절차 2단계, 관련자료 링크 1건 입력 후 저장 | 정상 저장 |
| 저장한 항목 수정으로 다시 열기 | 입력했던 RACI/절차/링크/사용자 정의 값이 그대로 복원됨 |
| 속성 스키마 스튜디오에서 내장 속성 표시 순서 변경 후 다이얼로그 재오픈 | 섹션 순서가 패널과 함께 바뀜 |

## TC-4. 내장 속성 노출 설정 연동

| 단계 | 기대 결과 |
|---|---|
| 속성 스키마 스튜디오에서 `RACI`(task 스코프) 숨김 처리 | 등록 다이얼로그를 다시 열면 RACI 위젯이 표시되지 않음 |
| 다시 노출 처리 | RACI 위젯 복귀 |

## TC-5. 검색 / 필터

| 단계 | 기대 결과 |
|---|---|
| 검색창에 이름 일부 입력 | 이름·설명 매칭 카드만 표시 |
| Task 유형 필터 선택 | 해당 유형 카드만 표시, 해제 시 전체 복귀 |

## TC-6. 수정 / 삭제

| 단계 | 기대 결과 |
|---|---|
| 카드 연필 아이콘 클릭 | 다이얼로그 제목 "Task 수정", 기존 값 프리필 |
| 이름 변경 후 저장 | 카드 이름 갱신 (중복 카드가 생기지 않음) |
| 휴지통 아이콘 → 삭제 확인 | 카드 제거 |
| 삭제 전 순서도에 적용해 둔 요소 확인 | 요소의 속성은 그대로 유지 (카탈로그 삭제 영향 없음) |

## TC-7. 데이터 검증 (선택)

- [ ] Supabase `task_catalog` 테이블에서 저장 행 확인:
  `tenant_id`가 현재 테넌트인지, `properties`에 `raci` / `procedure` / `manualLinks` / `description` / 사용자 정의 키가 있는지
