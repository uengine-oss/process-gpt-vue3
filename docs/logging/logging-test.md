# 활동 로그 수집 테스트 가이드

- 작성일: 2026-09-16
- 대상: `specs/002-activity-audit-logging` — 활성 페이지 전면 활동 로그 수집
- 환경: PAL 모드 + 프론트 dev 서버(8088). 활동 로그 확인 화면은 **관리자 콘솔 → 감사 로그(`/admin-console/audit-trail`)** 이며 관리자 계정만 조회 가능.

## 공통 준비 / 확인 방법

1. **PAL 모드 + 로그인 상태**에서 테스트한다. (비 PAL 빌드에서는 어떤 로그도 새로 적재되지 않아야 정상이다.)
2. 행위 수행 후 관리자 계정으로 **감사 로그 → "관리자 감사 로그" 탭**(기본 탭)을 연다. 이 탭이 곧 "활동 로그"다.
3. 필터: **액션** 드롭다운에서 기대 액션(예: "페이지 조회")을 선택 → 검색. **대상 유형** 필터로도 좁힐 수 있다.
4. 로그 적재는 비동기·무음(실패해도 화면 흐름을 깨지 않음)이므로, 행위 직후 목록을 새로고침해서 확인한다.

**DB 직접 확인** (선택):

```sql
select created_at, actor_username, action, target_type, target_id, target_name
from admin_audit_log order by created_at desc limit 20;
```

> 로그인/로그아웃은 별도 테이블(`auth_login_audit`) → **"로그인 이력" 탭**,
> 파일 다운로드는 `file_download_log` → **"다운로드 이력" 탭**에서 확인한다(§10, §11).

## 1. 페이지 조회 로그 (모든 대상 페이지 공통)

**대상 라우트**: `/process-architecture`, `/process-hierarchy`(프로세스 순서도), `/version-comparison`, `/review-board`(하위 포함), `/call-activity-management`, `/glossary`, `/organization`(및 `/organization-before`), `/admin-request`, `/analysis-dashboard`, `/admin-console/*` 전체 탭.

**절차**

1. 위 페이지들을 사이드바에서 하나씩 방문한다.
2. 활동 로그 탭에서 액션 = **페이지 조회(page_view)** 필터로 검색.

**기대 결과**

- 방문한 페이지마다 1건씩, 대상 유형 = **페이지**, 대상명 = 메뉴 한글명(예: "프로세스 체계도", "용어 사전", "감사 로그")으로 표시된다.
- 같은 페이지 안에서 쿼리만 바뀌는 이동(필터 변경 등)은 중복 적재되지 않는다. 다른 페이지로 갔다가 돌아오면 새 로그 1건이 추가된다.
- 감사 로그 화면 자체 방문도 "감사 로그" 페이지 조회로 1건 남는다.
- **프로세스 순서도(`/process-hierarchy`)는 예외**: 조회 중인 프로세스가 쿼리(`?id=`)로 전달되므로, 다른 프로세스로 전환할 때마다 별도 조회 로그가 남는다. 대상명은 "프로세스 순서도(프로세스명)" 형태이고 대상 id는 프로세스 id다. 단순 조회이므로 변경 내역 칸은 비어 있다.

## 9. 관리자 콘솔 (`/admin-console/*`)

기존에 적재되던 탭(속성 스키마, 보안 설정, Task 종류, KPI, 시스템 운영, 휴지통, 데이터 잠금 등)은 그대로 유지된다. 이번에 추가된 항목:

| 화면 | 행위 | 기대 액션(라벨) | 대상 |
|---|---|---|---|
| 속성 스키마 | 템플릿 내보내기 | `schema_export` (스키마 템플릿 내보내기) | 속성 스키마 |
| Task 카탈로그 | 등록 / 수정 / 삭제 | `task_catalog_create/update/delete` (Task 카탈로그 등록/수정/삭제) | Task 카탈로그 |
| 거버넌스 스튜디오 | 블랙리스트 추가 / 제거 | `governance_blacklist_add/remove` (거버넌스 블랙리스트 추가/제거) | 데이터 거버넌스 |
| 감사 로그 | 각 탭 CSV 내보내기 | `audit_log_export` (감사 로그 내보내기) | 감사 로그 |
| 보안 설정 | 정책 저장 | `security_settings_update` (보안 설정 변경 — 라벨 신규 표시) | 시스템 |
| 보안 설정 | 보존 기간 저장 | `audit_retention_update` (감사 로그 보존 기간 변경 — 라벨 신규 표시) | 시스템 |

**절차**: 각 화면에서 행위 수행 → 활동 로그 확인. 감사 로그 CSV 내보내기 로그의 변경 내역에는 내보낸 행 수(row_count)가 기록된다.

## 10. 로그인 / 로그아웃 (로그인 이력 탭)

로그인·로그아웃·로그인 실패는 활동 로그 탭이 아니라 **"로그인 이력" 탭**(`auth_login_audit`)에 적재된다 (IP·User-Agent는 서버측 기록, 위변조 불가).

**절차**

1. 로그아웃 상태에서 틀린 비밀번호 1회 → 올바른 로그인 1회 → 로그아웃 1회.
2. 관리자 → 감사 로그 → 로그인 이력 탭: 실패(사유 포함)/성공/로그아웃 3건 확인.

---

## 11. 파일 다운로드 (다운로드 이력 탭)

파일(첨부 등) 다운로드는 **"다운로드 이력" 탭**(`file_download_log`)에 적재된다. 화면에서 생성하는 내보내기(CSV/Excel 등)는 활동 로그의 `*_export` 액션으로 기록된다(§2, §9).

---

## 12. 회귀 확인 (필수)

1. **라벨 공백 없음**: 활동 로그 목록에서 액션·대상 유형 칸이 비어 보이는 행이 없어야 한다. (새 액션 코드가 라벨 맵에 모두 등록되었는지의 검증)
2. **필터 노출**: 액션 필터 드롭다운에 "페이지 조회", "용어 등록" 등 신규 항목이 보인다.
3. **비 PAL 모드**: 비 PAL 빌드에서 기존 화면 동작·콘솔에 변화가 없어야 한다 (신규 로깅은 전부 PAL 가드).
4. **흐름 무결성**: 네트워크를 끊거나 Supabase를 내린 상태에서 행위를 수행해도 기능 자체는 정상 동작해야 한다(로그만 조용히 실패, console.error 1줄).
5. **일반 계정 차단**: 일반 계정으로는 감사 로그 화면 접근/조회가 되지 않아야 한다(관리자 전용 RLS).
